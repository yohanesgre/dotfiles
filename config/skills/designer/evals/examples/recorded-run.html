Type scale and spacing (derived)

  • Base body/controls 16px, line-height 1.5. Help and card copy 13px / 1.45. Field labels 14px / 600. Card h2 18px / 1.3. Page h1 28px mobile, 32px ≥640px, line-height 1.2.
  • Spacing uses only the token steps (8/12/16) and their compositions: 24 = 16+8, 32 = 2×16, 48 = 3×16. No other values appear in this design.
  • No shadows anywhere. Structure comes from 1px borders; elevation is not part of this system.

Flow graph — C

Job: adjust reading and account preferences, and know exactly when they are saved. Cardinality: detail. Exactly one settings record per account; sections and fields are fixed units — no collection, no pagination, no live values. That is why this page has no list/refresh states; it has load, save, and permission states instead.

Happy path

Docs nav→ Settings · loadneeds: session + settings data→ Form · idle→ Edit field→ Dirty→ Save→ Saving→ Saved→ Form · idle

Branches

Saving→ Save failed→ Dirty · edits kept→ Try again→ Saving
Settings · load→ Load failed→ Try again→ Settings · load
Dirty→ Discard changes→ Form · idle · snapshot restored
Form · idle→ Reset preferences…→ Confirm dialog→ Staged defaults · dirty→ Save
Edit field→ Blur→ Invalid→ Inline error · fix→ Dirty

Submit with an invalid field: focus moves to the first invalid field; no request is sent. Submit with an empty diff is impossible — Save is disabled while clean.

Accessibility

  • Contrast: ink/paper 15.1:1; muted/paper 5.8:1; danger/paper 6.0:1; danger on danger-wash 5.3:1; ink on cyan-ink 4.6:1 (hover 5.3, active 4.8); control borders 3.2:1. Raw --cyan is 2.7:1 on paper — never text, never the only indicator; use it as a fill behind ink glyphs or as a 2px accent paired with text. Focus ring is ink (15.1:1) — cyan fails the 3:1 focus-appearance bar.
  • Focus visible: 2 px solid --focus, offset 1–2 px on every interactive element. Focus order: shell nav → h1 → cards top to bottom → save bar actions last. The dialog traps focus, Esc and Cancel close it, and focus returns to the “Reset preferences…” trigger.
  • Labels: every control has a visible label — text inputs wrap their label element; segmented and radio-style groups use fieldset + legend or an equivalent accessible group name; switches are checkboxes with role="switch", toggled by Space and by clicking anywhere in the row.
  • Errors: inline text at the field, aria-invalid on the control, error text referenced with aria-describedby. Color is never the only signal — every error carries an icon and a sentence. On submit with errors, focus moves to the first invalid field.
  • Announcements: save status text is role="status" (polite); save-failure banner and load error are announced as alerts; the saved toast is role="status" and is dismissible.
  • Targets: ≥44 px on mobile for every control and nav link; ≥40 px on desktop; the switch row is the full-width label, not just the 40×24 track.
  • Headings: one h1 (“Settings”), one h2 per card, no skipped levels. No content is conveyed by position or color alone.
  • Viewport: no horizontal scroll at 320 px. Long values scroll inside their input, never push the layout wide.
  • Dirty guard: leaving with unsaved changes triggers the browser’s standard unload confirmation; the save status announces “You have unsaved changes.”

Build order

  1. Tokens and base layout: page measure, cards, field grid, breakpoint 640.
  2. Field units: text inputs, labels, help, segmented control, switch, buttons — every state from the specimen grammar.
  3. Dirty tracking and the save bar (panels 02, 03).
  4. Save flow: saving, toast, failure banner (panels 03, 04, 05).
  5. Void states: loading skeleton, load error, partial section error, view-only (panels 06, 07, 08, 09).
  6. Reset flow and dialog (panels 11, 13).
  7. Long-content pass (panel 10) and accessibility pass.
  8. Motion and reduced-motion.

Open items for the parent

  1. Nav link: the design assumes Settings is added to the docs shell nav and marked aria-current="page". Confirm, or point this at the intended navigation pattern.
  2. Derived semantic values: muted/line/danger fills, type sizes, and motion tokens live in this artifact because assets/tokens.css defines none of them and must not be edited. Promote them to the token file in a dedicated token task, or keep them page-local?
  3. No theme control, by design: the token set defines one light palette. A Light/Dark/System control would promise a dark mode the design system does not define. If dark mode is wanted, it needs a full token pass before any control appears.
  4. Explicit save: saving is a deliberate action, with a browser unload guard while dirty. Confirm — an autosave variant would change the flow graph, not just the bar.
  5. Reset scope: the “Reset preferences” card and confirmation dialog are included. Drop them if the page should carry no destructive action.
  6. Single page, not tabs: all sections live on one scroll. If the section count grows, tabs would re-route the flow graph (needs a new panel set).
