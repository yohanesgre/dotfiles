## Operational gotchas

Durable failure modes and caveats learned the hard way — keep in mind when editing this config:

- **MCP credentials do not depend on the daemon process environment.** OpenCode's background service can be spawned from a TUI with an empty `OPENCODE_BROWSER_USE_API_KEY`; `service set env` is also ignored by the respawn path. The Home Manager `writeBrowserUseKey` activation writes `~/.config/browser-use/key` (0600) from `.env.toml` on every switch. The `browser-use-mcp` wrapper reads that file, exports `OPENAI_API_KEY` only to its child, and execs pinned `uvx --from 'browser-use[cli]==0.13.10' browser-use --mcp`; `opencode.jsonc` has no key env indirection. This removes the browser-use daemon-startup environment footgun. `jev-mcp` uses the same file-based pattern with `~/.config/typesafe/key` (0600), written by `writeTypeSafeKey`. Do not reintroduce `{env:TYPESAFE_API_KEY}` for jev: an empty string is not nullish and would win over the key file (precedence `TYPESAFE_API_KEY ?? JEV_API_KEY ?? key file`) — poisoning every judgment with an auth error.
- **`mode: subagent` is not a hard primary gate.** The subagent tool rejects children with `mode: primary`, but `opencode run --agent <subagent-only>` resolves the name directly and bypasses the TUI filter — `researcher`/`steward`/`vision` can be launched as primary. No config blocks it (no `agent.use` policy action).
- **Model variants must be an ARRAY.** `providers.<id>.models.<model>.variants` is an array of `{ id, settings?, headers?, body? }`; a record is rejected (`skipped malformed recognized value`) and drops the whole provider block.
- **Code Mode needs two explicit allows.** A subagent needs `execute` (`* deny` alone yields `No tool named "execute" is currently available`) **and** a nested per-tool allow for every MCP tool it calls — the normalized `<server>_<tool>` action (e.g. `codegraph_*`, `jev-mcp_*`); without it the wildcard deny blocks the nested call. Plain `jev_*` / `jev_check` actions do not match server `jev-mcp`.
- **Untracked files are invisible to the Nix flake.** New hm-managed files must be `git add`ed before `hm-switch`, or the switch will not see them (skills are exempt — their activation symlinks repo paths).
- **Never `opencode auth login opencode`** (Console device-OAuth) — it stores an OAuth credential that outranks the OpenCode Go API-key account and is rejected by zen/go (`401 Unauthorized`). Use `opencode auth login opencode-go --method key` (or `/connect` → OpenCode Go → API key).
- **jev-mcp 0.5.0 exposes 6 question-pack tools** (`jev_classify`/`jev_score`/`jev_check`/`jev_ask`/`jev_triage`/`jev_models`) — the README's `jev_review`/`jev_verify`/`jev_assess_change_risk`/`jev_check_requirement` set does not exist in this build.
- **`experimental.subagent_depth` counts ancestors** (top-level = 0, child = 1) and must be the nested key — the top-level SDK key is ignored by the runtime.

### Browser-use runtime attachment

- **Attach mode:** browser-use attaches to the user's running **Google Chrome** via CDP, using the real profile with no copy or isolation. `home/modules/browser-use` provisions repo source `config/browseruse/config.json` to `~/.config/browseruse/config.json`; the default `browser_profile` uses `{ "id": "0638303e-…", "default": true, "cdp_url": "http://127.0.0.1:9223" }` for the local `Dev` profile (`--profile-directory="Profile 2"`).
- **Declarative activation:** `browserUseSyncConfig` performs a cmp-guarded copy on every switch. It intentionally copies instead of symlinking from `/nix/store` because browser-use rewrites `config.json`/tool state; dotfiles source wins after a switch. `browserUseChromeDesktop` renders `~/.local/share/applications/google-chrome.desktop` and `com.google.Chrome.desktop` from `/usr/share/applications/*.desktop` with `sed` on every switch, adding `--remote-debugging-port=9223 --user-data-dir=/home/yohanes/.config/google-chrome` to every `Exec` line, then runs `update-desktop-database` when available. Chrome runs with `--remote-debugging-port=9223 --user-data-dir=/home/yohanes/.config/google-chrome --profile-directory="Profile 2"`. For Chrome 154 with the default data directory, the port is accepted only when explicit `--user-data-dir` is present; the switch's presence satisfies its restriction.
- **Run requirement and caveats:** Chrome must be running from an overridden launcher or browser tools fail. The port is localhost-only, but local processes can control the browser. The agent acts on real profile tabs two-way; `browser_close_all` closes real tabs. The Vivaldi route is abandoned and its desktop override was reverted; a live Vivaldi instance may hold port 9222 until restart (harmless).
- **Live verification:** 2026-09-24: `browser_navigate` opened a new tab in the user's Chrome and `browser_extract_content` returned the page heading.

## Luvus: `opencode.depth` module (2026-09-26)

Successor to the reverted `luvus-state` overlay (revert entry above): Luvus module (Bun/TS) at `config/luvus/modules/opencode-depth/` that watches OpenCode's public HTTP/SSE surface and publishes **authoritative** pane status via UHP `agent.report` (authority `integration_report`, source `opencode/depth`), plus per-child/headless-lane dock rows, bar counts, and aggregate AGENTS titles. The shipped `luvus-v2` integration still reports root-session identity only (ownership) — it is luvus-managed and untouched.

- **Activation:** `home.activation.luvusOpencodeDepthModule` (`home/modules/luvus/default.nix`) runs `luvus module link` on every switch when the module is unregistered or points elsewhere; warn-only, never fails the switch. `link` runs the `[[startup]]` launcher, which starts one detached watcher and exits (single-instance via atomic pidfile under `LUVUS_MODULE_STATE_DIR`; `pane.created`/`pane.closed` hooks revive it).
- **Commands:** `luvus module run opencode.depth start|stop` (idempotent start; stop signals the pid and clears a stale pidfile). Monitor pane is manual — `luvus module pane open opencode.depth monitor --placement overlay` (`[[panes]]` are not auto-started by `link`). Watcher log: `opencode-depth.watcher.log` in the module state dir; never contains the module token or the OpenCode password. `SIGTERM`/`SIGINT` releases every lease and clears dock/bar/titles so Luvus falls back to native detection.
- **Settings:** `source` (`opencode/depth`), `ttl_s` (900; renewed at TTL/3, floor 60), `max_rows` (16), `bar` (true), `title` (true).
- **Status model:** over each mapped pane's session tree (root + descendants by `parentID`) — pending permission → `blocked`, active execution → `working`, terminal execution within 120 s → `done`, else `idle`. Exact `agent_session` mapping wins; otherwise pane matched to a root by `cwd` (newest active drain first), ambiguous `cwd` skipped and logged, never guessed. Any live shell of a mapped session tree keeps the pane `working` past the execution-terminal event: `shell.created` (`data.info.metadata.sessionID` + `data.info.id` + `location.directory`) adds, `shell.exited` (`data.id`) removes, `shell.deleted` ignored. Dock/monitor live-work presence is subtree-scoped — a headless root survives while any descendant is active or holds a live shell — while the 120 s done window stays root-only. Backfill/reconcile queries `GET /api/shell?location[directory]=<enc>` per known directory, ordered tracked-shell directories, then event directories, then session directories, deduped and bounded at 16 (excess sliced); a failed directory keeps its known shells, a successful empty result drops only that directory's, the zero-directory unscoped `/api/shell` fallback reconcile is skipped while any tracked shell still has an unknown directory (so a successful empty response cannot wipe it), and the merge is guarded by a monotonic `shellVersion` so an SSE exit during a fetch cannot be resurrected.
- **Limits:** the model-facing shell tool cannot request `background: true` — only harness-only shells run detached, and the public shell payload has no background/foreground discriminator, so every live shell counts as working (background *subagent* sessions are still mapped, via `parentID`); `unmappedRoots()` is subtree-scoped for live-work presence — a headless root stays in the dock/monitor while any descendant holds a live shell or is active past the 120 s done window — but the done window itself stays root-only, so an idle long-terminal root still disappears; durable-log replay is resync-via-poll, not replay; live `blocked` is not reproducible under the global `permission: allow` in `opencode.jsonc`. Requirements: Luvus ≥ 0.14.2, a running OpenCode shared service, and `bun` on the **Luvus server** process path.
