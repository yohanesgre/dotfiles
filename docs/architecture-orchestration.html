Run sequence — from /goal to a closed plan

  1. entry /goal <text> — the only un-gated human step
    Loads the goal skill with the request as $ARGUMENTS; intake is the one place the pipeline waits on a plain reply. commands/goal.md:5, goal/SKILL.md:73-86
  2. Route: simple = 1 lane, complex = 1..N
    Classified on contract surface (schema/API/design authority/shared files), never file count; “when unsure, it is complex”. goal/SKILL.md:88-114, orchestration/SKILL.md:130-155
  3. Design + protocol: wave graph into plan.md
    design-thinking graphs; waves ordered by dependency, one owner per node, file ownership per lane so parallel tracks never collide. goal/SKILL.md:116-149
  4. Open the plan — status/<plan>/
    Template → plan.md; status.md = PLAN; acceptance frozen BEFORE any lane runs. goal/SKILL.md:151-178, work-plans/SKILL.md:37-66
  5. Pre-gate validation (advisory)
    plan-check.sh (strict) + jev open triage (advisory) — a red plan is fixed before the gate, never after. goal/SKILL.md:191-195, work-plans/SKILL.md:154-160
  6. human Execution gate — last human gate
    Approves waves, lanes, resolved models, worktrees/branches, and the whole lifecycle (branch → commit → push → PR → auto-merge on green CI). No approval = no execution; lapse 72h. Simple route → fast path (ack = go). orchestration/SKILL.md:157-175
  7. Isolate — every worktree before any setup
    git worktree add from origin/main per lane; setups then run concurrently (independent paths); per-worktree clean check inside. Collision → FAST EXIT, never unisolated. orchestration/SKILL.md:183-206
  8. Layout — master column + lane grid, once per wave
    lane-layout.ts: orchestrator stays left at full height, lanes tile ~2:1; more than 6 lanes overflow to extra lane-only tabs, never squeezed. orchestration/SKILL.md:219-231
  9. Brief + model — self-contained, explicit
    Brief = delegated subgraph (WHY/Nodes/Edges/Docs/Acceptance/Gate/Forbidden/Boundary); model is read verbatim from the role agent's md and passed with --model — the md pin does NOT apply to a primary opencode run session. orchestration/SKILL.md:233-256
  10. 2026-09-29 Dispatch is a BATCH, not a loop
    Fire EVERY lane of the wave before waiting on anything — luvus pane run is a non-blocking text+Enter submission. Serialize only shared-file lanes and the steward subagent; dispatch-one/wait-one is now an explicit deviation. orchestration/SKILL.md:278-289, references/lane-dispatch.md:13-20
  11. Join — wave-wait.ts [--any] [--timeout]
    200 ms poll over N return files; --any lets an early lane's reviewer spawn while siblings still run. A return file's appearance means the runner finished; rc=0 is real completion. Timeout ≠ dead lane — check luvus pane status, re-wait. orchestration/scripts/wave-wait.ts:5-21
  12. Verify + review wave — per lane, then merge
    End of wave: gates + frozen acceptance + graph compare (extra/missing node = deviation). Reviewer per lane, async, stable lane↔reviewer map; jev diff pre-filter first; a lane closes out on its own green — no sibling wait. orchestration/SKILL.md:325-388
  13. PR → auto-merge → loop guard
    Green + met → commit, push, PR (body = result + gate tails + deviations); CI green → auto-merge. Loop guard: 3 iterations/wave without progress → park; hard cap 5/plan → FAILED. Policy-blocked → park + report, never poll. orchestration/SKILL.md:390-400, :451-455
  14. close Plan close-out — DONE | FAILED
    Close every lane pane → remove merged worktrees/branches → plan-check.sh + jev closure judgment → report.md/status.md/TIMELINE → icm_memory_store. The plan is not DONE until its panes are closed. orchestration/SKILL.md:405-419

goal — plan authoring (Phases 0–3)

  • One plan of record: status/<plan>/plan.md; a writing-plans artifact is input folded into it, never a second plan. goal/SKILL.md:129-136
  • Acceptance frozen before any lane executes — one verifiable criterion per work item, each with its verify command. goal/SKILL.md:174-178
  • Lanes only when parallel: the simple route deletes the lanes section rather than inventing a lane to fill the shape. goal/SKILL.md:169-170

orchestration — guardrails

  • Main-session guard: the orchestrator edits only status/** + memory; a self-made code edit is reverted and re-dispatched. orchestration/SKILL.md:83-93, :469-476
  • Hardened gate for steward: serialized, named files only, no commit/push, verify-then-accept (out-of-scope hunk → revert + re-dispatch). orchestration/SKILL.md:338-352
  • Break points: FAST EXIT (env/binary/worktree collision/model gap) stops one lane; WAIT parks it and continues others; secrets = the only halt-everything. orchestration/SKILL.md:424-459
  • Evidence rule: a bare “tests pass” is never green — gate output tails are pasted into the lane report. orchestration/SKILL.md:359-361

workers — lanes & subagents

  • Lane: swe (implementation) or designer (design artifacts) in a luvus pane, cwd = its worktree; the pane persists through the loop and closes only at plan DONE/FAILED. orchestration/SKILL.md:96-102, :312-323
  • Boundary: brief (delegated subgraph IN) → <slug>-return.md (implemented graph OUT, rc= line); extra/missing node = deviation. orchestration/SKILL.md:68-76, :291-306
  • Read-only: architect foreground, researcher fans out leaves, reviewer one per lane async; they never mutate. orchestration/SKILL.md:110-119
  • One mutating subagent only: steward (upkeep) — never a lane, never parallel. orchestration/SKILL.md:103-109

jev — advisory at four points (+ tracking)

  • Gate: jev_check on the frozen plan — a no is surfaced, the human still decides. references/jev-layer.md:13-16
  • Dispatch: jev_ask over proposed lanes — disjoint files, independent outputs, self-contained prompts, batch-dispatched (added 2026-09-29). references/jev-layer.md:17-24
  • Review pre-filter: jev_triage over each lane's diff as a path item (read server-side, never in context) — scope · acceptance · secrets · offscript; passing does NOT skip the reviewer. references/jev-layer.md:33-40
  • Tracking: work-plans open/close judgments stay advisory; plan-check.sh stays authoritative. work-plans/SKILL.md:154-168

Tooling

lane-layout.ts bun · once per wave

Locates the anchor pane via UHP snapshot, splits panes, parks each shell in its worktree, applies one atomic layout.apply per tab. Exit 0 ok · 1 error · 2 usage.

lane-wait.ts bun · one lane

File-sentinel watch + Effect timeout, 200 ms poll, default 120 s; prints last 4000 chars. Exit 0 seen · 1 timeout · 2 argv.

wave-wait.ts bun · new 2026-09-29

Joins N return files; --any returns on the first (early reviewer spawn); default 600 s. Exit 0 all/≥1 · 1 timeout with missing listed · 2 argv.

plan-check.sh bash · work-plans

Artifact lint: 3-line heartbeats/status, state enum, DONE|FAILED needs report.md, TIMELINE row. Exit 0 GREEN · 1 RED · 2 usage.

lane runner generated per lane

opencode run --auto --model … --agent … tee'd live, then rc= + atomic rename onto the return file as the LAST step — the file's appearance means the runner finished.

Fire-and-forget dispatch observability
