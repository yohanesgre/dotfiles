Event lifecycle — one real run

  1. dispatch Runner records timing around the agent
    The orchestrator writes brief + runner from the canonical template; the runner captures START/END ms around opencode run. cli-reference.md:140-144
  2. Lane return — atomic, then the log call
    The return file lands (rc semantics unchanged), then the runner appends the lane event — wrapped in || true so logging can never fail the lane. cli-reference.md:153-156
  3. Event write — guarded JSONL
    runlog.sh validates key names (reserved ts/kind/repo skipped), tags the event with the main repo name (worktree-correct), builds one line with jq, appends to ~/.local/state/orchestration/runs.jsonl; missing jq or any failure → silent skip, exit 0. scripts/runlog.sh:22,28-48
  4. Plan close-out — the plan event
    At DONE/FAILED the orchestrator appends plan with wall, lanes, prs, iter. SKILL.md:420-421
  5. Report — aggregate, don't judge
    run-report.sh casts string fields and renders lanes/plans/failures/slowest; an empty log prints “no runs logged yet” (exit 0). scripts/run-report.sh:16-23,40-71
  6. Improve / fix
    Failures become rework items; slowest lanes become tuning targets. Evidence stays per-repo, next to the plans it describes.

runlog.sh — writer invariants

  • Advisory, never fatal: guarded on jq, every step swallows errors, exit 0 — a logging failure never fails a lane/run. scripts/runlog.sh:1-4,22
  • Reserved keys skipped: ts, kind and repo are added by the writer; unsafe key names are ignored by an allow-list. scripts/runlog.sh:42
  • jq does all escaping: the line is built from --arg pairs via $ARGS.named — no hand-rolled JSON. scripts/runlog.sh:47-48
  • Central path: $ORCH_LOG override, else ~/.local/state/orchestration/runs.jsonl; the repo field resolves via git-common-dir (worktree-correct) — lanes in worktrees tag the main repo. scripts/runlog.sh:28-35

run-report.sh — reader invariants

  • Read-only + advisory: missing jq → message + exit 0; never mutates the log. scripts/run-report.sh:12
  • Every field is a string: explicit casts (rcnum, dur_s); malformed values fall back instead of aborting the report. scripts/run-report.sh:26-30
  • Sections: lanes by repo/plan · plans · failures · signals (repeated failures, iter>1) · slowest top-10 · recent fixes. scripts/run-report.sh:38-99
  • Out-file optional: writes and cats when given, stdout otherwise; ORCH_LOG wins over the positional log arg, ORCH_REPO filters to one repo. scripts/run-report.sh:14-16,110

Log file — status/log/runs.jsonl

  • Central by design: one file for all repos — a single report diagnoses every project; the report itself needs no git. cli-reference.md § Run log
  • Kinds: lane (plan, lane, slug, role, model, worktree, start_ms/end_ms/dur_ms, rc) and plan (verdict, wall_s, lanes, prs, iter); new kinds are additive.
  • Attribution: every event carries repo — the main repo name, worktree-correct; non-git dirs fall back to the cwd basename. Override the path with ORCH_LOG. runlog.sh:28-35

Watch items

No automated test for runlog/report quality

Verification today is the manual e2e sample. A tiny fixture log + expected-report check would make regressions detectable. config/skills/orchestration/scripts/

Malformed numeric fields cast silently data

rcnum/dur_s fall back to 0/-1 on unparseable values — a corrupted dur_ms could read as “fast”. Fields are machine-written, so treat suspicious zeros as anomalies. run-report.sh:22-27

No rotation / time filter growth

The central runs.jsonl grows across all repos monotonically; the report always reads the whole log. Lines are tiny, but long-lived setups deserve rotation.

Plan event is convention, not enforced completeness

A skipped close-out line = a missing plan row; lanes still log. Enforcement would need a plan-check addition. SKILL.md:420-421
