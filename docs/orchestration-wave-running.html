What the orchestrator does while they run

  • Waits once: wave-wait.ts polls all return files — it is the orchestrator's only idle state. orchestration/SKILL.md:278-289
  • Reacts per lane: a landed file → its reviewer spawns (background, read-only); rc≠0 → FAST EXIT/WAIT, never review. :375-388
  • Triages server-side: jev reads the full return artifact and lane diff as path items — never into orchestrator context. references/jev-layer.md:24-40
  • Never codes: main-session guard — while lanes run, the orchestrator touches only status/** + memory. orchestration/SKILL.md:83-93

What is NOT parallel

  • Shared-file lanes: migrations, lockfiles, CHANGELOG, submodule gitlinks — one owner, serialized through one lane. references/edge-cases.md:9-12
  • steward: the one mutating subagent (control checkout, no worktree) — one at a time, never beside a lane touching the same files. orchestration/SKILL.md:338-352
  • Dependent waves: an edge gates the next wave; wave-to-wave is the plan's outer loop, not a per-lane loop. orchestration/SKILL.md:78-81

Failure while running

  • Wait timeout ≠ dead lane: fire-and-forget dispatch has no ack — check luvus pane status, re-wait; only a dead pane with no return file is WAIT + re-dispatch. references/lane-dispatch.md:88-96
  • Lane died mid-run: resume the pane with opencode --session (state lives in the worktree). orchestration/SKILL.md:315-317
  • Reviewer fail/timeout: not green — retry, or self-review that lane against the checklist. :445-446
  • Secrets: the only halt-everything — kill that lane immediately. :457-458

Watch items — while the wave is live

Slow lane vs dead lane look identical observability

No ack on luvus pane run; the return file is the only signal. Timeout handling depends on the orchestrator remembering to check pane status. references/cli-reference.md:162-164

Provider rate limits cap real concurrency external

Three opencode run sessions share one provider quota; the batch fires them, but upstream may queue them. Bulk saves wall clock only up to the provider's limit. orchestration/SKILL.md:278-289

Panes persist by design — grid reflows only on close UI

A finished lane keeps its pane and scrollback until plan DONE/FAILED; the visible grid is not a task board. orchestration/SKILL.md:225-231
